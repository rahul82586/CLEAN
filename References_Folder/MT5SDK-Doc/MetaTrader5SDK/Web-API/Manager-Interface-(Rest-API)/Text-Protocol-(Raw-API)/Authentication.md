# Authentication (#authentication)

To start executing manager commands on the server, the client must switch to Web API mode and get authenticated on the server.

To switch the interaction of the Web client with the access server to the Web API mode, the client needs to send a packet that contains only the special header MT5WEBAPI. Only after receiving this packet, the server starts handling the commands of the MetaTrader 5 Web API.

Two commands are used for authentication:

  * AUTH_START — authentication start command.
  * AUTH_ANSWER — a command of reply to an authentication request.



Authentication is done in several steps, at which the server and the client send commands with different parameters.

  * [Request to Start Authentication (#client-start)](Authentication.md#client-start)
  * [Start of Authentication on the Access Server (#server-start)](Authentication.md#server-start)
  * [Response to the Server (#client-answer)](Authentication.md#client-answer)
  * [End of Authentication (#server-answer)](Authentication.md#server-answer)



Web Client | Trading Server  
---|---  
"AUTH_START|LOGIN=xxxx|..." => |   
| <= "AUTH_START|RETCODE=xxx ssss|SRV_RAND=xxxx|..."  
"AUTH_ANSWER|SRV_RAND_ANSWER=xxx|CLI_RAND=xxx|..." => |   
| <= "AUTH_ANSWER|RETCODE=xxx ssss|CLI_RAND_ANSWER=xxx|..."  
  
<a id="client-start"></a>
## Request to Start Authentication (#client-start)

A client should send a request to start authentication using the AUTH_START command, for example:
    
    
    LLLLKKKKFAUTH_START|VERSION=484|AGENT=TEST|LOGIN=14|TYPE=MANAGER|CRYPT_METHOD=NONE|\r\n

The following parameters separated the "|" character are passed in the command:

  * VERSION — the version of the Web API. The version should not be below 484.
  * AGENT — an arbitrary name of the Web agent. The name must not be empty.
  * LOGIN — the login of an account under which authorization should be performed.
  * TYPE — the type of account. Only one value is currently supported, which is 'manager'. This means connection using a [manager account](../../../Configuration-Interfaces/Managers/IMTConManager.md). The account used fully determines connection permissions, including the [list of IP addresses](../../../Configuration-Interfaces/Managers/IMTConManagerAccess.md) allowed for connection.
  * CRYPT_METHOD — the method of encryption: NONE — no encryption, AES256OFB — AES. If this parameter is not specified, the server will run in the AES256OFB mode by default. 



<a id="server-start"></a>
## Start of Authentication on the Access Server (#server-start)

In response to the authentication start command, the access server sends the AUTH_START command, in which a response code and a random sequence are passed.
    
    
    LLLLKKKKFAUTH_START|RETCODE=0 Done|SRV_RAND=d4e005317e38bc0c349a51a0d73a07eb|\r\n

The following parameters separated the "|" character are passed in the command:

  * RETCODE — a response code and its string description. 0 means successful completion.
  * VERSION_ACCESS — version of the access server that is used for connection to the trade server.
  * SRV_RAND — a random 16-byte sequence in the Hex format, generated by the server. A password should be applied to this sequence when sending a response.



<a id="client-answer"></a>
## Response to the Server (#client-answer)

After receiving a random sequence, a client should apply a password (hash of the password) to it and send it to the server using the AUTH_ANSWER command:
    
    
    LLLLKKKKFAUTH_ANSWER|SRV_RAND_ANSWER=8b67609a264764a528ec8c709ab71df2|CLI_RAND=34b6bccab8bfebdf462d1312043df1cc|\r\n

The following parameters separated the "|" character are passed in the command:

  * SRV_RAND_ANSWER — MD5 hash of the random sequence and the password hash. 
  * CLI_RAND — a client's random sequence for authenticating on the server. The sequence must be in the Hex format with 16 byte size. 



<a id="hash"></a>
### Password Hash (#hash)

The hash of the password is calculated the following way:
    
    
    Hash hash=MD5(MD5('Password')+'WebAPI')

Six characters of the WebAPI are added to the MD5 hash of the password and once again an MD5 hash is obtained from the result. Then, when sending to the server, the obtained hash is once again combined with the random sequence of the server. Hash is taken from the resulting value, which is then sent to the server. This ensures the maximum security of authentication.

An Example of Forming of SRV_RAND_ANSWER:
    
    
    password hash=MD5(MD5('Password1')+'WebAPI')=904ba8ecb16273d2f0ae9c3b8a023752
    SRV_RAND=73007dc7184747ce0f7c98516ef1c851
    //--- Calculation formula: SRV_RAND_ANSWER=MD5(password hash+SRV_RAND)
    SRV_RAND_ANSWER=MD5(904ba8ecb16273d2f0ae9c3b8a023752+73007dc7184747ce0f7c98516ef1c851)=77fe51827f7fa69dd80fbec9aa33f1bb

A step by step example of how SRV_RAND_ANSWER is formed:

Let's analyze Web Password=Password1 and SRV_RAND="73007dc7184747ce0f7c98516ef1c851".

1\. We calculate MD5 of the password in Unicode (in this case, unicode string Password1):
    
    
    MD5('Password1')

The result as bytes:
    
    
    [ 236,46,146,255,112,191,70,145,174,12,104,224,47,220,108,34 ]

2\. We add a one byte WebAPI string as 6 bytes to the byte result:
    
    
    MD5('Password1')+'WebAPI'

'WebAPI' is represented as = [ 87,101,98,65,80,73 ]. The result as bytes:
    
    
    [ 236,46,146,255,112,191,70,145,174,12,104,224,47,220,108,34,87,101,98,65,80,73 ]

3\. Get the final hash of the password as MD5 of the byte result from step 2:
    
    
    MD5(MD5('Password')+'WebAPI')

The result as bytes:
    
    
    [ 144,75,168,236,177,98,115,210,240,174,156,59,138,2,55,82 ]

The result as a HEX string:
    
    
    904ba8ecb16273d2f0ae9c3b8a023752

4\. Combine the byte hash of the password from step 3 and SRV_RAND:
    
    
    MD5(MD5('Password1')+'WebAPI')+ [ 115,0,125,199,24,71,71,206,15,124,152,81,110,241,200,81 ]

Where [ 115,0,125,199,24,71,71,206,15,124,152,81,110,241,200,81 ] is the HEX string 73007dc7184747ce0f7c98516ef1c851 converted to a byte array:
    
    
    SRV_RAND = 73007dc7184747ce0f7c98516ef1c851 = [ 115,0,125,199,24,71,71,206,15,124,152,81,110,241,200,81 ]

The final result of the combination (two byte arrays are simply joined together):
    
    
    [ 144,75,168,236,177,98,115,210,240,174,156,59,138,2,55,82,115,0,125,199,24,71,71,206,15,124,152,81,110,241,200,81 ]

5\. We form the final SRV_RAND_ANSWER for response to the server as MD5 of the byte result from step 4:
    
    
    MD5(MD5(MD5('Password1')+'WebAPI') + [ 115,0,125,199,24,71,71,206,15,124,152,81,110,241,200,81 ]

The result as bytes:
    
    
    [ 119,254,81,130,127,127,166,157,216,15,190,201,170,51,241,187 ]

The result is converted to a HEX representation:
    
    
    77fe51827f7fa69dd80fbec9aa33f1bb

The final parameter in the response string is as follows:
    
    
    SRV_RAND_ANSWER=77fe51827f7fa69dd80fbec9aa33f1bb|

<a id="server-answer"></a>
## End of Authentication (#server-answer)

After authenticating a client through a trade server, an access server sends a response using the AUTH_ANSWER command:
    
    
    LLLLKKKKFAUTH_ANSWER|RETCODE=0 Done|CLI_RAND_ANSWER=8b67609a264764a528ec8c709ab71df2|CRYPT_RAND=HEX_256_bytes\r\n

The following parameters separated the "|" character are passed in the command:

  * RETCODE — a response code and its string description. 0 means successful completion.
  * VERSION_ACCESS — version of the access server that is used for connection to the trade server.
  * VERSION_TRADE — version of the trade server.
  * CLI_RAND_ANSWER — MD5 hash of the client's random sequence and the password hash. The sequence is in the Hex format, with the size of 16 bytes.
  * CRYPT_RAND — a random sequence of the server, using which the final encryption sequence should be formed. The sequence is in the Hex format, with the size of 256 bytes (512 characters).



To authenticate a server on a client, the same algorithm as for client's authentication on the server is used. In the CLI_RAND_ANSWER parameter, the server sends an MD5 hash of a client's random sequence and a password hash.

An Example of Forming of CLI_RAND_ANSWER:
    
    
    password hash=MD5(MD5('Password1')+'WebAPI')=904ba8ecb16273d2f0ae9c3b8a023752
    CLI_RAND=4db98fec17aab4dc5a240bdc659e8395
    //--- Calculation formula: CLI_RAND_ANSWER=MD5(password hash+CLI_RAND)
    CLI_RAND_ANSWER=MD5(904ba8ecb16273d2f0ae9c3b8a023752+4db98fec17aab4dc5a240bdc659e8395)=1732021b1b332f51660b2b315eed3a35
